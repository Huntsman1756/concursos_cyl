# CSS legacy normalization audit

## Scope and evidence

This source audit accompanies the computed-style baseline in
`analysis/design-system-normalization-before.json` and its Markdown rendering.
The baseline was captured from the Vite production preview before the
normalization rules were changed. The after audit is the corresponding
production-build measurement after the changes.

The cascade was reviewed across the four relevant layers:

1. `src/styles/global.css` contains the original application layout and feature
   rules.
2. `src/styles/visualRefresh.css` contains the later refresh layer, including
   the legacy page-shell, breadcrumb, result-tab and training rules.
3. Feature sheets contain route-local geometry and typography.
4. `src/styles/salida.css` is the token-driven implementation layer and now
   owns the normalized shared primitives at lines 1761–1917.

The intent is to move the contract to shared tokens and named primitives while
retaining feature-specific meaning, evidence order, responsive behavior and
the existing `visualRefresh` layer where it still supplies valid behavior.

## Normalization decisions

| Primitive      | Token / rule                                                                                         | Applies to                                                                  | Deliberate exception                                                                        |
| -------------- | ---------------------------------------------------------------------------------------------------- | --------------------------------------------------------------------------- | ------------------------------------------------------------------------------------------- |
| Page gutter    | `--page-gutter` and compatibility `--grid-gutter`                                                    | Header, main canvas, footer, breadcrumbs, mastheads, filters and results    | Approved Home media can remain composition-led; it still aligns its outer content edge      |
| Interior title | `--type-page-title` / weight 700                                                                     | FP, Occupation, Offers, Centers, Compare, Resources, Open Data, Methodology | Home display title uses `--type-display-home`                                               |
| Eyebrow        | `PageEyebrow`, `--type-eyebrow`, primary color and uppercase                                         | Existing page eyebrows and Home                                             | FP/Occupation result mastheads remain optional because breadcrumb already names the journey |
| Masthead       | `.page-masthead` shared base class with optional breadcrumb, eyebrow, H1, lede, metadata and actions | Interior page headers                                                       | Existing metadata/actions retain their order and meaning                                    |
| Controls       | `--type-control`, `--control-height`, `--radius-control`                                             | Buttons, selects, text inputs and evidence navigation                       | Radio/checkbox glyphs remain native-size; print styling remains secondary                   |
| Panels         | `--radius-panel`, `--radius-card`, `--panel-padding-sm/md`                                           | Forms, callouts, cards, evidence and methodology blocks                     | Components keep different panel/card/callout roles                                          |
| Section rhythm | Existing `--stack-section`, `--stack-block`, `--stack-related` roles                                 | Shared section heads and masthead-to-content transitions                    | Home's editorial media composition remains content-led                                      |

## Legacy CSS disposition

`visualRefresh.css` was not deleted. Its valid header, navigation, breadcrumb,
footer, focus and responsive behavior remains in place. The normalized rules in
`salida.css` establish the shared contract after the feature sheets load, while
feature CSS retains only role-specific geometry, data hierarchy and responsive
exceptions.

The after audit must be read together with the screenshots. A legacy selector
remaining in source is not itself a failure; the relevant question is whether
its computed value still creates an unapproved divergence.
