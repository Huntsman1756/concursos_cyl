# FP coverage expansion audit contract

Each numbered slot follows one bounded lifecycle:

`not_started → in_progress → completed | deferred | discarded`

`startedAt` is recorded before research. `not_started` and `in_progress` records may omit terminal evidence and outcomes; terminal states require them. A slot has at most 60 modeled active minutes; reviewer time is explicitly excluded. Terminal work records `completedAt`, the reviewed commit and its actual git commit timestamp, limitations, exact official-output evidence, accepted and rejected CNO relations, and deterministic baseline/current match IDs.

The frozen ranking's `officialOutputLabels` are research seed labels, not an exhaustive output inventory. Each terminal attempt carries an authoritative `officialOutputInventory`; its labels are the frozen source-order list and the `officialOutputReviews` must match it exactly, once each, with an exact contiguous quote and an accepted or rejected disposition. Completed reviews must also contain every ranking seed in order. A deferred or discarded review may instead record an authoritative inventory that exposes a seed mismatch, preserving the evidence and limitation without promoting the slot to completed. Accepted relations require independent INE/SEPE classification evidence. Aliases must preserve the reviewed occupation boundary; multi-word aliases use the existing strict policy, while the only permitted single-token tuple is `encofradores / occupation:cno11:7111 / EOC01M / approved_single_token`. Generic or broadened aliases are rejected.

Modality variants collapse to their canonical base qualification identity and never increase the distinct count. Each accepted overlay is recomputed in memory against the frozen baseline. The validator stores exact sorted per-program IDs and their union; declared counts are not trusted. Any non-target delta, altered match ID, stale snapshot, or duplicate base fails closed.

Only completed attempts may publish. The injected public loader returns a strict complete manifest-addressed object: `manifestAddressed: true`, sorted unique `relationKeys`, and at least one sorted unique `resourcePaths` accepted by the generated-resource catalog (manifest, permitted foundation assets, or immutable snapshot resources). For completed attempts its relation keys equal the accepted relations exactly; deferred, discarded, and non-terminal attempts have an empty published relation-key set and publish none. A terminal deferred/discarded record may retain rejected relation keys in `publicParity` as audit decisions, but those keys are never public resources. Rejected occupations, aliases, and links must not occur in manifest-addressed public resources. The mandatory reviewed-base exclusions are always applied before the non-terminal return and again during terminal validation. Publication is a later terminal operation; this contract does not build data or perform network access.

Accepted/rejected relation occupations must correspond exactly to accepted/rejected output dispositions. Programme/output relation evidence must use an exact candidate source URL; a CNO relation may additionally use an authoritative INE/SEPE URL discovered in the matching classification row. In every case its `(sourceUrl, sourceQuote)` pair must match the audited official-output or matching classification row for that CNO; aliases must also occur as a bounded phrase in that exact quote; placeholder and non-official domains fail closed. If a frozen candidate contains a demonstrably wrong official source URL, only a `deferred` attempt may record `sourceDrift` with the frozen candidate URL, the corrected authoritative URL, and a reason; the corrected URL must be the only evidence URL outside the frozen source list, and no public relation may be emitted. The bounded one-word tuple is additionally linked to the A1 read-only review artifact. Accepted multi-word aliases require a successful injected `matchAlias` result, while rejected aliases are still subject to the same tuple and evidence policy. The validator accepts injected ranking, attempt, deterministic offer calculator, alias matcher, public-resource, A1-artifact, and commit-timestamp loaders so future slots can be tested with temporary fixtures and read-only dependencies; terminal-only loaders are not invoked for non-terminal attempts. Its default timestamp loader reads `git show -s --format=%cI`. Terminal attempts must carry snapshot ID and SHA-256 hash values that exactly match the deterministic computation.
