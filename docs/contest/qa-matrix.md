# Contest readiness QA matrix

This matrix records the stable browser checks that must pass before final evidence is captured. The desktop Playwright project is configured at 1280×800; the final capture manifest deliberately uses 1440×900 or 360×800 and must be rerun after the coverage freeze.

| Route/state                                                | Desktop                                                    | Mobile 360×800                 | Expected evidence                                                                                               | Claim class        |
| ---------------------------------------------------------- | ---------------------------------------------------------- | ------------------------------ | --------------------------------------------------------------------------------------------------------------- | ------------------ |
| `/` root and navigation                                    | `contest-readiness.spec.ts` — root journey                 | same test in `chromium-mobile` | heading, principal navigation, reviewed-coverage loading completion, overflow, Axe, request/console diagnostics | invariant + freeze |
| `/desde-fp` before submit                                  | `contest-readiness.spec.ts` — FP search                    | same test in `chromium-mobile` | official combobox, ready state, direct SPA entry                                                                | invariant          |
| `/desde-fp/EOC01M` reviewed result                         | `contest-readiness.spec.ts` — bounded current matches      | same test in `chromium-mobile` | reviewed cycle, bounded offer cards, no global employment claim                                                 | freeze             |
| `/desde-fp/HOT01M`, `/desde-fp/SSC01M`, `/desde-fp/EOC01M` | `contest-readiness.spec.ts` — honest empty/matched states  | same test in `chromium-mobile` | no unsupported “no employment/jobs” wording                                                                     | freeze             |
| `/desde-fp/COM01M` reviewed with zero current offers       | `contest-readiness.spec.ts` — reviewed before/after search | same test in `chromium-mobile` | eight reviewed groups and an honest snapshot-bounded zero-result state                                          | freeze             |
| `/comparar` with higher-level selection                    | `contest-readiness.spec.ts` — dual official scopes         | same test in `chromium-mobile` | Spain and Castilla y León scopes remain separate                                                                | invariant + freeze |
| `/metodologia` with source disclosures opened              | `contest-readiness.spec.ts` — methodology sources          | same test in `chromium-mobile` | official links, limitations, normalized evidence                                                                | invariant + freeze |
| representative privacy journey                             | `contest-readiness.spec.ts` — no persistence/tracking      | same test in `chromium-mobile` | no cookies/storage/account UI/third-party requests                                                              | invariant          |

Every journey also requires one level-1 heading, no remaining loading indicator or `aria-busy="true"`, no horizontal overflow above one pixel, zero serious/critical Axe violations, no failed requests, no HTTP error responses, and no browser console errors. Direct result routes exercise SPA fallback semantics locally; the base-prefixed Pages build is a release gate, not a substitute for this direct deep-link check.

Volatile claims—snapshot identity, counts, approved relations and aliases, matched/zero/deferred sets, and deployment provenance—remain rerun-only until the coverage freeze and final deployment records exist. No screenshot is asserted or generated by this matrix.
